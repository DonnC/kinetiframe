# Governance

This page explains how decisions about KinetiFrame are made and how you can take on a bigger role.

## Roles

**Contributors** are everyone who opens an issue, comments, reviews, draws, writes or submits a
pull request. You don't need permission to contribute.

**Maintainers** review and merge pull requests, triage issues, cut releases and look after the
project's direction. The current maintainer is [Donald Chinhuru (@DonnC)](https://github.com/DonnC),
who started the project.

## How decisions are made

Most decisions happen in the open, in issues and pull requests. A change is merged when a
maintainer approves it and the checks pass.

Larger changes need a discussion before code is written. These include a new module, a change to
a saved file format, a new dependency, or a change to how a core workflow feels to use. Open an
issue or discussion that describes the problem and the options you considered.

When a decision affects the architecture or will be hard to undo, it is written down as an
architecture decision record in [docs/architecture/decisions](docs/architecture/decisions). That
way future contributors can see what was decided and why.

If people disagree, maintainers look for consensus first. If none forms, the maintainer makes the
call and explains the reasoning on the issue.

## Becoming a maintainer

KinetiFrame would like more maintainers, including people who focus on art, documentation or
community rather than code. If you have contributed regularly for a few months, reviewed others'
work, and want to help, ask in a discussion or contact the maintainer. New maintainers are added
by agreement of the existing maintainers and listed in this file.

## Areas and reviewers

[.github/CODEOWNERS](.github/CODEOWNERS) lists who is asked to review changes in each part of the
repository. As the team grows, areas such as the engine, design system and sample art can have
their own reviewers.

## Changes to this document

Changes to governance are proposed as pull requests and stay open for at least a week so
contributors can comment.
